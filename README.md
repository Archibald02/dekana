# Декана

Конкурсный прототип цифрового деканата с вымышленными данными. Главная показывает ближайшую пару и действия, которые требуют внимания: перенос, аттестацию и статус заявки.

## Запуск

Нужен Node.js 24 или новее. Выполните `npm run dev` и откройте http://localhost:3000. Зависимостей npm нет. Данные сохраняются в `.data/dekana.sqlite`. Данные входа передаются жюри в конкурсном комментарии.

На хостинге с Node.js запускайте команду из каталога проекта, задайте `PORT`, подключите постоянный диск для `.data` и настройте HTTPS через обратный прокси. За прокси укажите `PUBLIC_ORIGIN` равным адресу сайта без завершающей косой черты. Этот вариант рассчитан на один экземпляр приложения. Облачная версия собирается через `npm run build`: ES-модуль Worker в `dist/server/index.js`, привязка D1 `DB`, миграции в `drizzle/`.

## Путь для жюри

1. Войдите под первым студентом. На главной нажмите карточку «Перенос пары». Откроется нужный день, занятие выделено. Преднастроенный демонстрационный перенос относится к 23 ноября 2026.
2. Вернитесь на главную и откройте карточку аттестации. «В календарь» скачает файл ICS с московским временем события.
3. Закажите справку и сохраните адрес её карточки. История покажет событие «Заявка принята».
4. Войдите под сотрудником. В очереди откройте заявку, нажмите «Взять на рассмотрение», затем «Выдать демо-PDF». Для заявки «Вопрос деканату» сотрудник отправляет ответ.
5. Вернитесь в аккаунт первого студента и откройте карточку заявки. На ней доступны история и скачивание демонстрационного документа. Во втором студенческом аккаунте та же ссылка показывает «Заявка не найдена».
6. В кабинете сотрудника можно опубликовать один актуальный перенос для выбранной демогруппы. Заполните дату учебного дня, время пары и новую аудиторию. После обновления страницы перенос виден студенту нужной группы.

В верхней панели студента есть помощник. Он отвечает по данным открытого кабинета и ведёт к нужному разделу. Он использует локальные правила разбора вопроса.

## Проверки и устройство

Перед `npm test` задайте `DEKANA_NORD_PASSWORD`, `DEKANA_VEGA_PASSWORD` и `DEKANA_STAFF_PASSWORD` из конкурсного комментария. Тесты проверяют сессии, разделение двух студентов и сотрудника, историю, скачивание, календарь и публикацию переноса.

Оценки и базовое расписание формируются из локального набора в `src/students.js`. Сотрудник меняет демонстрационный перенос и обрабатывает заявки в пределах этого набора. Сессии, заявки, история, прочтение уведомлений и опубликованные переносы сохраняются в базе. Сервер проверяет роль и владельца при каждом защищённом действии, включая скачивание PDF. В базе хранится SHA-256 от идентификатора сессии, пароль проверяется через PBKDF2-SHA256 с индивидуальными солями. Источник запросов записи проверяется на сервере.

Оформление, знак и пиктограммы оригинальные. Интерфейс использует системные шрифты. В демонстрационных PDF встроены подмножества Open Sans, лицензия указана в `fixtures/`.
